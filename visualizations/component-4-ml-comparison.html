CURRENT SYSTEMWhat the repository does now
TARGET SYSTEMWhat the completed research system should do
1

Activity content

Rounds mainly contain prompt, options and correct answer.

Skill 2 has adaptive variants; other skills mostly do not.

→

Research item bank

Every scored task has item ID, Sinhala KC tags, difficulty, distractor type, equivalent variants and allowed scaffolds.

2

Response evidence

Main signal is correct/incorrect plus latency and touch counts.

An answer completed after highlighting may still increase mastery as “correct”.

→

Standard learning event

Stores first independent answer, final answer, attempts, assistance, latency, C1/C2 features and task-specific evidence.

3

Learner estimation

Provisional BKT values are almost identical across KCs.

One global IRT theta mixes visual, phonological and language skills.

→

Two trained learner models

Fitted BKT: mastery for each Sinhala KC.

Multidomain IRT: item difficulty and separate visual, phonological and comprehension abilities.

4

Support decision

Skill 2 follows hand-coded state machines.

Other skills receive a generic fallback; current C1/C2/C3 gateway values are mocked.

→

Two trained decision models

Fatigue/struggle classifier: predicts when support or a break is needed.

Constrained contextual bandit: selects the best approved scaffold.

5

Next action in Flutter

Adaptive navigation is explicitly accepted only for Skill 2.

Other activities continue using their local fixed sequence.

→

Shared adaptive contract

Every scored activity understands: retry, easier equivalent, harder equivalent, scaffold, confirmation, pause and stop.

6

Stopping and evidence

SE calculation exists but is unused. Decisions may be stored more than once.

No trained-policy evaluation across all skills.

→

Safe stopping and validation

Minimum/maximum items, unassisted confirmation, calibrated uncertainty and fatigue limits.

One auditable record and child-level validation.
